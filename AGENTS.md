# Rails Base Agent Coordination

## Task routing

When acting as the project coordinator, classify each new task before implementation.

Delegate to the Documentation Specialist when the primary outcome is any of the following:

- Creating, updating, reviewing, or reorganizing README.md or files in docs/.
- Documenting setup, bootstrap, configuration, development, deployment, recovery, release, or handoff workflows.
- Verifying that commands, paths, versions, links, environment variables, and public configuration comments are documented accurately.
- Identifying broken links, stale instructions, duplicated guidance, or undocumented setup requirements.

Use the profile in .agents/documentation-specialist.md for the delegated task.

## Boundaries

- Keep the project coordinator responsible for prioritization, user decisions, integration, and final validation.
- Do not route application behavior, database, CI, security policy, dependency, or deployment-configuration changes to the Documentation Specialist.
- If a documentation task identifies an implementation gap, report it to the coordinator for assignment to the appropriate specialist.
- Delegate only bounded tasks with a clear outcome. Review the specialist's report before accepting changes.
